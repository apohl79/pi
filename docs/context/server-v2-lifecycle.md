# Server V2 lifecycle

`PiServerV2` validates `maxFrameLength` as a positive safe integer no larger than uint32 and `handshakeTimeoutMs` as a positive safe integer no larger than Node's timer delay. Startup is shared across concurrent callers through one promise. Connection teardown is guarded by per-connection close/disconnect promises and a server-wide runtime disposal guard, so transport callbacks cannot dispose the same runtime twice. A handshake remains non-ready until bounded replay completes; replay is accepted only for a session present in the authorized `listSessions()` snapshot.

Session reads use the same handshake-visible session set before calling the service runtime opener; connection errors and rejected closes still run disconnect cleanup. Server close awaits an in-flight startup promise before closing listeners, preventing a listener from being started after close returns.

Listener shutdown is best-effort and ordered as a lifecycle barrier: all listener close promises are awaited with `Promise.allSettled`, each rejection is reported, and active connections/runtimes are then closed. A listener startup failure marks the server non-restartable and applies the same cleanup to every configured listener and any connections accepted before the failure.

V2 authorization is connection-scoped: only session IDs in the handshake `listSessions()` snapshot may be attached, and session reads/goal reads/turns require an attachment on that connection. Process, agent, input-request, and operation IDs retain their owning session and require the caller to hold that session attachment; unknown or cross-session IDs return generic request errors. Restored event history is sorted by sequence before replay/cursor filtering, and every outbound frame (including protocol errors) uses the configured `maxFrameLength`.

Handshake execution is single-flight per connection, and replay is sequential, authorized by the handshake snapshot, and bounded to 256 events and 16 MiB of encoded frames. Attach reuses an existing connection runtime and coalesces concurrent opens per session; failed first attaches dispose the newly opened runtime. Plan reads/updates and detach require an attached session. Transport send failures are reported and close the connection, while event fanout uses `allSettled`; connection close awaits runtime disposal and reports disposal failures. Operation errors are sanitized and capped, and diagnostics are best-effort so recording failures cannot prevent operation execution. Once a runtime accepts an operation, `runOperation` is scheduled from a `finally` continuation so persistence, response, or accepted-event fanout failures cannot prevent execution; those side-effect failures remain server diagnostics (and transport failures still trigger connection cleanup).
